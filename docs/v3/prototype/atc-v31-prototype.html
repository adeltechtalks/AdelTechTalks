Prompt Arena

Entry → active → scoring → completion, playable. Three formats: Choose and Repair are graded by the server; Create is self-assessed against a worked model answer and is not evidence of anything.

Launch gate 9 challenges 3 shown here Choose deterministic Repair deterministic Create self-assessed

The launch gate. Prompt Arena opens with nine challenges — three Choose, three Repair, three Create — or /playground/ does not open. This is a publication gate of the kind v2.x already enforces on Gear photographs: the engine ships complete; the route waits for content. Three are built here to demonstrate all three formats.

Create had to be corrected. A self-assessed score earns completion XP and nothing else. It cannot satisfy a score-gated badge and it cannot be published as a verified achievement — which is why prompt-architect ships visible and locked until Phase 4 brings model-assisted scoring, rather than shipping as a badge that quietly grades itself.

Motion

Five tiers, four act registers, and one strictly ordered feedback sequence. Flip the Motion toggle to Reduced and replay anything — the fallback is a complete experience, not a shortened one.

Ceiling for the whole feedback chain 2000ms Animate transform + opacity only Max 3 elements moving per viewport

The feedback sequence, in order

Result → XP → level → badge. Each step waits for the previous one. Firing them together produces a slot machine, which is what “no confetti” was protecting against in a different costume.

Every state change is announced in words, in order — “Scored 84 out of 100. 50 XP awarded. Badge earned: Prompt Builder.” A screen-reader user gets the whole sequence without any of the motion, which is the test of whether the motion was ever load-bearing. Publish flow

The security fix, made operable. Send a request and watch the server refuse it. This is the contract in V3_API_SURFACE.md §2, running.

What was wrong in v3. The migration granted authenticated a direct insert on achievement_verifications, checked only with auth.uid() = user_id. That proves the row is about you. It proves nothing about whether you earned what it claims. Any signed-in person could mint a public, crawlable, branded page asserting any badge in the catalogue — with the site's own branding vouching for it.

2  rateLimit(`publish:${user.id}`, 10, '1h')         → 429

5  DERIVE the snapshot server-side — display_name, title, earned_at,
     score, level, xp — every field from the proving record
6  id = gen_random_uuid()                            server-side, always
