# /diagram-story

**Explain a relationship or process with a drawn structure rather than prose.**

| | |
|---|---|
| Mode | Both |
| Best story beats | explanation, proof |
| Best content types | how-it-works, architecture, workflows, systems |
| Required assets | a relationship worth drawing |
| Optional assets | icons or object frames at the nodes |
| Max combinations | one supporting skill — usually `/sketch-overlay` |

## When to use it
The content is structural and a paragraph would describe what a picture could show. A diagram earns its place only when the shape carries meaning.

## When NOT to use it
The diagram is decorative — boxes and arrows restating a list. If the arrangement could be alphabetical without loss, it is a list.

## Composition logic
One mechanism per diagram. Consistent node sizes for equivalent things. Direction of flow unambiguous and constant.

## Motion logic
Build in flow order, one element at a time, then hold. Never animate all nodes at once.

## Brand OS rules
Line weight, radius and type from the profile. Node colour carries meaning or is neutral — never decorative variety.

## Platform considerations
Needs space and reading time: carousel, long-form, or a slide. Never a thumbnail.

## Arabic / English considerations
Flow direction follows reading direction; mirror the layout for RTL rather than reversing arrowheads only.

## Example
Three stages connected left to right, each with one label, the middle stage emphasised.

## Anti-patterns
Twelve boxes · arrows crossing · a diagram that needs a paragraph to explain the diagram.
