# /fold-reveal

**Perform the act of unfolding so the format change is felt before it is read.**

| | |
|---|---|
| Mode | Motion |
| Best story beats | reveal, transformation |
| Best content types | foldable devices, adaptive content, responsive design, format explainers |
| Required assets | a device frame or a canvas that can credibly open |
| Optional assets | a second frame showing the opened state |
| Max combinations | one supporting skill — usually `/paper-reveal` |

## When to use it
The story is that something opens, widens or gains space, and that change is the point. Strongest when the viewer's own screen is the subject.

## When NOT to use it
There is no device or canvas imagery, or the unfold is decorative rather than meaningful. An unfold that reveals nothing new is an animation, not an argument.

## Composition logic
Start closed and narrow, end open and wide. The revealed area must contain something worth revealing — new content, not the same content enlarged.

## Motion logic
One continuous opening on a decelerating curve. The content inside must reflow, not scale: scaling makes it look like a zoom and loses the whole idea.

## Brand OS rules
Motion duration and easing from the profile's motion charter. No added light effects unless the profile allows them.

## Platform considerations
The first frame is a thumbnail and must work closed. On short vertical, the unfold happens within the first second or it is wasted.

## Arabic / English considerations
If a label names the two states, keep numeric ratios and established Latin terms in Latin.

## Example
A narrow vertical frame opening to a wider one, the composition re-laying itself rather than stretching.

## Anti-patterns
Unfolding to reveal the same layout scaled up · unfolding twice · adding sparkle to the seam.
