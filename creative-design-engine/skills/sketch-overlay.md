# /sketch-overlay

**Mark the frame by hand — an arrow, a circle, an underline, a written word — so a person is visibly pointing at something.**

| | |
|---|---|
| Mode | Both |
| Best story beats | curiosity, proof, joke, explanation |
| Best content types | reviews, explainers, reactions, tutorials |
| Required assets | a frame with an identifiable focal point |
| Optional assets | calm space beside the point for a written note |
| Max combinations | this IS usually the supporting skill — do not add a third |

## When to use it
There is one specific thing in the frame the viewer must look at, and pointing at it adds information. The hand-drawn quality is what makes a composition read as made rather than generated.

## When NOT to use it
There is nothing meaningful to mark. An annotation used to demonstrate that annotation exists is the single most common failure of this skill. Also never on a placeholder — a pending asset is not something real.

## Composition logic
One marked idea per frame. The mark sits ON the subject, not floating in empty space beside it. Hand-drawn paths, never geometric shapes — a perfect circle reads as a UI element.

## Motion logic
Draw on in one stroke, fast, then hold. Never loop, never pulse.

## Brand OS rules
Colour comes from the profile's designated annotation colour, which must not be its primary or action colour — an annotation must never be mistakable for interface. Handwriting uses the profile's sketch face.

## Platform considerations
Survives small sizes well; often the last readable element in a feed.

## Arabic / English considerations
Many handwriting faces carry no Arabic glyphs. In RTL compositions the written note must be digits or an established Latin term, or it silently falls back and stops being handwriting. Verify the face before using a word.

## Example
A curved arrow from the hook to a product's hinge, with a two-character note beside it.

## Anti-patterns
Three arrows · a circle around the whole subject · emoji · arrows as a style rather than a pointer.
