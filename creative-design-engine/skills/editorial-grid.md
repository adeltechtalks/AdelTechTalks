# /editorial-grid

**Compose with a real grid and real whitespace so the piece reads as considered rather than assembled.**

| | |
|---|---|
| Mode | Static |
| Best story beats | explanation, proof, CTA |
| Best content types | carousels, long-form covers, multi-point explainers |
| Required assets | copy, and optionally imagery |
| Optional assets | any number of images |
| Max combinations | one supporting skill — usually `/number-impact` |

## When to use it
The piece has structure worth showing — several related points, a hierarchy, a sequence. Also the right answer when photography is weak and type must carry.

## When NOT to use it
On a thumbnail. A grid needs reading time a feed does not give, and editorial restraint at feed size reads as emptiness.

## Composition logic
Asymmetric by default. One dominant element, everything else clearly subordinate. Whitespace is structural, not leftover.

## Motion logic
_Static skill — no motion logic._

## Brand OS rules
Grid, gutters, margins and type ramp from the profile. Never invent a spacing step.

## Platform considerations
Carousel and long-form. On vertical short-form it is almost always the wrong choice.

## Arabic / English considerations
Grid mirrors for RTL; the hierarchy does not change.

## Example
A three-column slide with one column carrying a large figure and the other two carrying short supporting lines.

## Anti-patterns
Even columns of equal weight · a grid with nothing dominant · using the grid as a container for unrelated items.
