# /feature-callout

**Name one feature on an object and say why it matters.**

| | |
|---|---|
| Mode | Both |
| Best story beats | proof, explanation, demonstration |
| Best content types | product reviews, spec explainers, tutorials |
| Required assets | a product or UI frame where the feature is visible |
| Optional assets | a drawn mark tying label to feature |
| Max combinations | often IS the supporting skill; at most one other |

## When to use it
One feature is the reason the piece exists and it is visible in the frame.

## When NOT to use it
More than two features compete. Three callouts is a spec sheet, and a spec sheet is not a composition. Split into slides or scenes.

## Composition logic
Label sits beside the feature, connected by proximity or a drawn line — never floating. The object stays dominant; the label is support.

## Motion logic
Label draws in after the object has settled. Never before — the viewer must see the thing before being told about it.

## Brand OS rules
Label type and colour from the profile. Callout is not an accent-colour opportunity.

## Platform considerations
Small labels die at feed size. On a thumbnail, at most one callout and it must be readable at 168 px.

## Arabic / English considerations
Established feature names stay in their original language per the profile's language rules.

## Example
A single label beside a hinge, joined by a short drawn line.

## Anti-patterns
Four callouts · labels in a legend away from the object · a callout naming something invisible in the frame.
