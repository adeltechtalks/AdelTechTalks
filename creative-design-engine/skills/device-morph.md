# /device-morph

**Morph one device or canvas state into another to show that a single source serves both.**

| | |
|---|---|
| Mode | Motion |
| Best story beats | transformation, explanation |
| Best content types | multi-device content, responsive systems, adaptive video, cross-platform |
| Required assets | two device or canvas states of the same content |
| Optional assets | a shared element to carry through the morph |
| Max combinations | one supporting skill — usually `/freeze-frame-note` |

## When to use it
The argument is that one thing adapts into another. The morph makes continuity visible in a way two separate shots cannot.

## When NOT to use it
The two states are genuinely different content. A morph then claims a relationship that does not exist, which is a lie told smoothly.

## Composition logic
Hold one element constant across the morph — a subject, a headline, a colour field — so the eye tracks continuity rather than seeing a cut.

## Motion logic
Morph the container, reflow the contents. Contents must re-lay themselves; a uniform scale reads as a zoom and destroys the point.

## Brand OS rules
Easing and duration from the profile. Both states use the same palette and type scale — the change is shape, not identity.

## Platform considerations
Costly at short durations. On a very short vertical, prefer a hard cut with matched framing over a rushed morph.

## Arabic / English considerations
Both states carry the same copy; do not translate mid-morph.

## Example
A 9:16 composition becoming a 4:3 one, the subject holding position while the text re-stacks.

## Anti-patterns
Morphing between unrelated shots · morphing and cutting in the same beat · a morph slower than the attention it buys.
