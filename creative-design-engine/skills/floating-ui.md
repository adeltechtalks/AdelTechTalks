# /floating-ui

**Lift interface elements off their screenshot so the interface becomes the subject.**

| | |
|---|---|
| Mode | Both |
| Best story beats | demonstration, explanation, proof |
| Best content types | software, AI tools, app reviews, feature launches |
| Required assets | a screenshot or UI capture |
| Optional assets | a device frame, a ground, a drawn mark |
| Max combinations | one supporting skill — usually `/sketch-overlay` |

## When to use it
The product is software and one part of the interface is the point. Extracting that part makes it legible at sizes where a full screenshot is not.

## When NOT to use it
The whole interface matters. Floating fragments of a UI that must be read as a whole destroys the context that made it meaningful.

## Composition logic
One or two extracted elements, larger than life, over a held-back version of the full screen. The extracted piece is sharp; everything else recedes.

## Motion logic
Elements lift and settle once. No continuous float — idle motion reads as a screensaver.

## Brand OS rules
Ground, shadow and radius from the profile. Do not restyle the UI — it is evidence, and restyled evidence is not evidence.

## Platform considerations
Excellent for thumbnails: solves the unreadable-screenshot problem. On square previews keep the extracted element centred.

## Arabic / English considerations
If the UI is in one language and the copy in another, that is fine — do not translate a screenshot.

## Example
A single panel lifted from a blurred application window, one drawn circle on the control that matters.

## Anti-patterns
Five floating elements · a redrawn fake UI · drop shadows heavy enough to detach the element from reality.
